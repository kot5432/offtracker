# Phase 6: 仮説候補の設計

更新: 2026-10-14

## 目的

セッションの記録から考えられる理由を、利用者が振り返るための候補として提示する。AIは原因を確定せず、候補の採用・修正は利用者が行う。評価、叱責、生産性スコアは扱わない。

## 実装方針

1. 疑似データで入力項目、候補の品質、画面上の表現を先に確認する。
2. ローカル側で許可した項目だけを仮説生成用データに変換する。AI出力の根拠は入力内のActivity/結果参照にし、画面用の事実文はローカルで組み立てる。
3. 生成部分はプロバイダーに依存しない境界にする。現時点ではAI事業者を選ばず、外部呼び出しもしない。
4. 送信先、送信される具体的な項目、利用者の同意を決めてから外部AI接続を別途実装する。

## 入力データ契約

許可する項目:

| 項目 | 形式 | 用途 |
|---|---|---|
| `purpose` | 目的文 | セッションで取り組む内容の文脈 |
| `activities[]` | `activity_type`, `duration_seconds`, `purpose_relation` | 行動の種類、長さ、目的との関係 |
| `result` | `result_level`, `actual_duration_minutes` | 結果区分と実績時間 |

Activityは時系列順を保つ。順序が候補の根拠になるためで、日時や細かい時刻は送らない。

含めない項目:

- Raw Event、イベントID、セッションID
- アプリ名、プロセス名、サービス名、ウィンドウタイトル、URL
- 正確な開始・終了時刻
- `result_description` や `what_wasnt_done` の自由記述
- `applications_used`、`services_used`、`event_ids`

目的文自体にも個人情報が含まれる可能性がある。外部サービス接続を将来行う場合は、目的文を送ることも含めて送信前に説明し、明示的な同意を求める。

## 出力データ契約

各候補は次を持つ。AI出力の `evidence` は説明文ではなく、入力中の事実を指す参照とする。Rustの `render_hypothesis_evidence` が参照先のActivity・結果から表示文を組み立てる。これにより、存在しないActivityや結果を根拠としてAIが書くことを防ぐ。候補のタイトル・説明自体は推論を含むため、断定や入力外の事実がないか別途確認する。

```json
{
  "title": "調査から実作業に戻るまでの時間が、進み方に影響した可能性",
  "description": "記録された範囲から考えられる一つの見方です。原因を確定するものではありません。",
  "evidence": [
    "activity:0",
    "activity:1",
    "result"
  ],
  "confidence": "low"
}
```

- `evidence` は `activity:0` の形式でActivity、`result` で結果を参照する。存在するActivity番号か結果参照かをRust側で検証し、画面用の根拠文はローカルの入力から作る。候補文に入力にない感情、意図、エラー、予定を補わない。
- 確信度は根拠の量と直接性を表す。活動時間が長いだけで「高い」としない。
- 構造検証ではタイトル120字以内、説明600字以内、候補不足の説明240字以内、1候補あたり根拠参照8件以内に制限し、未定義フィールドは拒否する。
- 候補同士は異なる説明にする。同じ事実を言い換えただけの水増しをしない。
- 3件に届かない場合も、根拠を持つ候補があれば1〜2件を示し、不足理由を添える。根拠を持つ候補がない場合は、原因を推測せずその旨を伝える。
- 「3件以上」は十分な記録がある場合の目標とし、すべてのセッションで満たす必須条件にしない。
- AIの出力は構造検証し、候補は最大3件とする。形式不正・根拠なし・禁止情報の混入があれば表示しない。

## 疑似データ例

`docs/mock-sessions/phase-6-hypotheses.json` を参照。プレビューでは3つの架空パターンを切り替えられる。Reflection画面から「仮説候補の表示例を見る（疑似データ）」を開き、活動の種類・時間・目的との関係・結果を根拠参照から組み立てた文と、表示候補を確認できる。候補例は画面・品質検討用で、実際の生成結果や実データの分析結果ではない。

例で確認する点:

- 「調査18分 → 連絡12分 → 作成5分」という順序と各時間が根拠に反映される。
- 連絡の目的関係が「不明」であることを、目的外だった証拠として扱わない。
- 結果が一部完了だったことだけで、原因や能力を断定しない。
- 記録からは分からない事情を、候補の事実として書き足さない。
- 複数候補のうち連絡に関する2候補が重複していないかを確認し、根拠を分けられない3件目を表示しない。
- 目的完了かつ短い記録では、原因候補を無理に作らず「原因候補を挙げる根拠はありません」と表示する。
- 1分未満で関係がすべて不明の記録では、未完了の理由を推測せず、根拠不足を表示する。
- 複数活動の例では、同じ連絡記録を使う候補が重複していたため3件から2件に変更し、2件にとどめた理由を表示する。

## 品質レビュー（2026-10-14）

| パターン | 見直し結果 | 表示方針 |
|---|---|---|
| 複数活動・一部完了 | 調査時間の配分と、作業間に記録された連絡という2方向は示せる。連絡の影響と中断を別候補にすると根拠が重なる | 低い確信度の候補2件と「3件目は根拠が重複するため出していない」という注記 |
| 短い記録・目的完了 | 原因を説明する必要がなく、記録から脱線も確認されない | 仮説なし。候補を挙げる根拠がないと表示 |
| 短い記録・関係不明・一部未完了 | 1分未満で全Activityが不明。未完了の理由を見分けられない | 仮説なし。根拠不足と表示 |

この確認により、「各セッションで3件を必ず出す」条件は品質を損なうため採用しない。3件以上を示せる記録では目指すが、1〜2件なら不足理由を添え、根拠がなければ候補を表示しない。

## AI・サーバー方式の判断

### 比較上の前提

ChatGPT、GitHub Copilot、Cursorの個人向け契約は、開発者が各サービスを使うための契約であり、OffTracker利用者に推論APIを提供する契約とは分けて考える。ChatGPTとAPIの請求は別である。CopilotとCursorはコード作成支援のプランであり、OffTrackerへ組み込む推論先を決めるにはAPI料金・利用条件を別に確認する。

### 推論候補の概算

2026-10-14時点の公開価格を使った概算。1回あたり入力1,000トークン・出力500トークン、月1,000回で計算。日本語のトークン数、モデル品質、再試行、ホスティング、税などは含まず、性能の同等比較ではない。

| 推論候補 | 公開料金の例（入力/出力 100万tokenあたり） | 上記条件で1,000回 | データ・運用上の特徴 |
|---|---:|---:|---|
| OpenAI API `gpt-5.6-luna` | $0.20 / $1.20 | 約$0.80 | APIデータは既定で学習に使われない。濫用監視ログは通常最大30日保持。デスクトップにAPIキーを入れず、バックエンド経由にする |
| Gemini API `gemini-3.5-flash-lite` | $0.30 / $2.50 | 約$1.55 | 無料枠は低コスト試作向けだが送信内容が製品改善に使われる条件がある。実データを使うなら有料枠と条件を選ぶ。有料化は最低$5の前払いが案内されている |
| Cloudflare Workers AI `Llama 3.1 8B` | $0.045 / $0.384 | 約$0.24 | Workers AIには1日10,000 Neuronsの無料枠があり、公開条件では明示同意なしに入力・出力を学習や他サービス改善へ使わない。Workers有料プランは最低$5/月 |
| PC内ローカルモデル（例: Meta Llama） | 推論API料金なし | $0のAPI請求 | PC性能・モデル配布・更新・ライセンス対応が必要。端末外へ送らずに済むが、利用者PCでの応答速度と品質を実機評価する |

単価はそれぞれの公式料金・利用条件を参照: [OpenAI API料金](https://developers.openai.com/api/docs/pricing)、[Google Gemini API料金](https://ai.google.dev/gemini-api/docs/pricing)、[Cloudflare Workers AI料金](https://developers.cloudflare.com/workers-ai/platform/pricing/)、[Cloudflare Workers料金](https://developers.cloudflare.com/workers/platform/pricing/)。APIデータの扱い: [OpenAI](https://developers.openai.com/api/docs/guides/your-data)、[Gemini API追加規約](https://ai.google.dev/gemini-api/terms)、[Cloudflare](https://developers.cloudflare.com/workers-ai/platform/data-usage/)。

### ホスティングと開発用サブスクリプション

- Cloudflare WorkersはAPIゲートウェイとWorkers AIを同じ基盤で運用できる。小さく始めやすい候補だが、利用モデルの日本語品質を疑似データで比較する。
- Google Cloud Runはリクエストに応じて動き、無料のリソース枠がある。Firebase Cloud FunctionsはBlaze（従量課金）プランを必要とする。いずれもホスティング先であって、別の推論APIを使う場合はそのモデル料金が加わる。
- Firebase/Cloud Functionsの利用では、Firebase公式も予算通知・上限設定の確認を勧めている。上限の適用には遅延があり得るため、完全な即時停止とはみなさない。
- ChatGPT Plusは月額契約とAPI請求が分かれている。GitHub Copilot Proは$10/月、Cursor Proは$20/月の開発支援プランとして案内される。これらをOffTracker利用者のAI推論原価とは数えない。
- Meta Llamaはローカル実行候補になるが、モデルごとにコミュニティライセンス等の条件を確認する。モデルサイズ、配布手順、利用可能なGPU/メモリを決める前に、現時点で採用を確定しない。

参考: [Cloud Run料金](https://cloud.google.com/run/pricing)、[Firebase Functionsの料金要件](https://firebase.google.com/docs/functions/quotas)、[Firebase予算・支出上限](https://firebase.google.com/docs/projects/billing/spend-caps)、[ChatGPT/APIの別請求](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)、[GitHub Copilotプラン](https://docs.github.com/en/copilot/get-started/plans)、[Cursorプラン](https://cursor.com/pricing)、[Meta Llama 4ライセンス](https://dev.meta.ai/llama/llama4/license)。

### 現時点の推奨

PC内でQwen3 0.6B/1.7B/4Bを疑似3ケースで比較した結果、いずれも製品候補としては不採用。4Bは候補を抑制すべきケースで推測を生成し、1ケース約44秒かかり、実行後の空きメモリも小さかった。次は品質ゲートを実装・確認する。クラウド比較は認証情報と費用上限を用意できる場合に限り、疑似データだけで行う。どの方式でも合格するまではアプリへ接続しない。実セッションの送信は、送信内容・保存期間・同意画面を別途設計し、利用者の明示同意を得るまで行わない。
