# 画面遷移の再検討プラン

## 現在の画面遷移
Home → 記録開始 → 記録中 → 記録終了 → Result → Timeline → Reflection → Pattern

## オフtrackerの目的
「やろうと思っていたことができなかった理由を、自分の実際の行動から振り返るためのアプリ」

## オフtrackerのサイクル
1. 目的を設定
2. 実際に行動
3. PCが自動記録
4. 結果を記録
5. 行動・作業状況を振り返る ← Timeline
6. 「なぜできなかった？」を考える ← Reflection
7. 過去の記録と比較
8. 自分のパターンを理解
9. 次回の行動を考える

## 各画面の役割の再検討

### Home画面
- 目的を設定する
- 記録を開始/終了する

### Result画面
- 結果を記録する（達成度、できたこと、できなかったこと）
- **問題**: 結果を記録した後にTimelineを見るべきか？

### Timeline画面
- 行動・作業状況を振り返る（行動を把握する）
- 「なぜ」を考えるための材料を提供する
- **問題**: 画面遷移が多い

### Reflection画面
- 「なぜできなかった？」を考える
- 次回の行動を考える
- **問題**: TimelineとReflectionが分かれていると「なぜ」を考える材料が足りない

### Pattern画面
- 過去の記録と比較
- 自分のパターンを理解

## 改善案

### 案A: ResultとTimelineを統合
- Result画面にTimelineを埋め込む
- 結果を記録しながらTimelineを見て振り返る
- 画面遷移を減らす

### 案B: ReflectionとTimelineを統合
- Reflection画面にTimelineを埋め込む
- 「なぜ」を考える際にTimelineを見る
- 画面遷移を減らす

### 案C: 現在のまま改善
- Timelineの振り返り支援を強化
- Reflectionの「次の行動」を考える支援を強化
- 画面遷移はそのまま

## 推奨: 案B（ReflectionとTimelineを統合）

### 理由
- 「なぜ」を考える際にTimelineを見るのが最も自然
- 画面遷移を減らす
- 振り返りプロセスをスムにする

### 画面遷移（案B）
Home → 記録開始 → 記録中 → 記録終了 → Result → Reflection（Timeline埋め込み） → Pattern

### メリット
- 「なぜ」を考える際にTimelineを見る
- 画面遷移を減らす
- 振り返りプロセスをスムにする

### デメリット
- Reflection画面が複雑になる
- Timelineが小さくなる可能性
