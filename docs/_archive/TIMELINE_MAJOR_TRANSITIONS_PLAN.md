# Timeline画面再設計プラン（主要な遷移のみを表示）

## 現在の問題
- 細かい画面遷移をすべて表示すると、情報過多で全体像が見えにくい
- 短時間で複数のアプリを行ったり来たりしている場合、同じアプリのイベントが重なって見にくい

## Timeline画面の目的
- ユーザーが自分の実際の行動を客観的に把握する
- 時間の流れを理解する
- 目的とのズレを認識する
- 「なぜできなかった？」を考えるための材料を提供する

## 解決策: 主要な遷移のみを表示

### アプローチ
- **長時間のアプリ使用のみを表示**（例: 5分以上のイベント）
- **脱線ポイントをハイライト**（YouTube、X、Redditなど）
- **細かい遷移を表示しない**（1分未満のイベントを無視）

### 表示例
```
[VS Code (20分)] [Google (5分)] [YouTube (15分)] [VS Code (5分)]
19:00              19:20         19:25              19:40         19:45
```

### メリット
- 全体の流れが一目で分かる
- 細かい遷移がノイズにならない
- 脱線ポイントが明確に分かる
- 実装がシンプル

### デメリットと対処法

#### デメリット1: 細かい遷移の詳細が失われる
**対処法**: クリックで詳細表示を可能にする
- イベントをクリックすると、詳細情報（ウィンドウタイトル、正確な時間など）を表示
- 詳細ビューで細かい遷移を確認可能

#### デメリット2: 閾値の設定が難しい（5分？3分？）
**対処法**: デフォルト値を設定して検証
- 最初は3分をデフォルトとして設定
- ユーザーフィードバックに基づいて調整
- 将来的にはユーザーが閾値を調整できるようにする

## 実装手順

1. **イベントをフィルタリング**
   - 短時間のイベントを無視（デフォルト: 3分未満）
   - アイドル時間を無視（オプションで表示可能）

2. **連続イベントを結合**
   - 同じアプリの連続イベントを結合
   - 間隔が短いイベントを結合（例: 30秒未満）

3. **主要な遷移を表示**
   - 横方向に時間軸
   - 各イベントを横棒で表示
   - 色分けで目的関連・脱線・調査を区別
   - 時間軸を下部に配置

4. **脱線ポイントをハイライト**
   - YouTube、X、Redditなどの脱線アプリを目立つ色で表示
   - 脱線時間を強調

5. **詳細表示機能**
   - イベントをクリックすると詳細情報を表示
   - 詳細情報にはウィンドウタイトル、正確な時間などを含む

## 検証手順
1. Timeline画面を開く
2. 疑似データをロード
3. 主要な遷移のみが表示されているか確認
4. 細かい遷移が表示されていないか確認
5. 脱線ポイントがハイライトされているか確認
6. 全体の流れが見やすいか確認
7. イベントをクリックして詳細表示を確認

## 考慮事項
- 閾値のデフォルト値（3分？5分？）
- ユーザーによるカスタマイズ（閾値の変更）← 将来的な機能
- アイドル時間の表示（オプション）
