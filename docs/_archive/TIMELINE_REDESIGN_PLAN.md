# Timeline画面再設計プラン

## 現在の問題
- 細かい画面遷移をすべて表示すると、情報過多で全体像が見えにくい
- 短時間で複数のアプリを行ったり来たりしている場合、同じアプリのイベントが重なって見にくい
- ユーザーが「大まかな画面遷移」を見たいというニーズがある

## Timeline画面の目的
- ユーザーが自分の実際の行動を客観的に把握する
- 時間の流れを理解する
- 目的とのズレを認識する
- 「なぜできなかった？」を考えるための材料を提供する

## 解決策

### 推奨: 時間単位で集約した大まかな画面遷移

#### アプローチ
- 時間軸を一定間隔で分割（例: 5分単位、10分単位）
- 各期間の主要なアプリを表示
- 短時間のイベントを結合

#### 表示例（5分単位で集約）
```
時間: 19:00-19:05  19:05-19:10  19:10-19:15  19:15-19:20  19:20-19:25  19:25-19:30  19:30-19:35  19:35-19:40  19:40-19:45
アプリ: VS Code        VS Code        VS Code        VS Code        Google         YouTube        YouTube        YouTube        VS Code
```

#### メリット
- 全体の流れが一目で分かる
- 細かい遷移がノイズにならない
- 脱線ポイントが明確に分かる
- 時間の流れが理解しやすい

#### デメリット
- 細かい遷移の詳細が失われる
- 間隔の設定が難しい（5分？10分？）

### 代替案1: イベントを間引く
- 1分未満のイベントを無視
- 短時間のイベントを結合
- 現在の実装に近い

### 代替案2: 主要な遷移のみを表示
- 長時間のアプリ使用のみを表示
- 脱線ポイントをハイライト
- 細かい遷移を表示しない

## 実装手順（推奨案）

1. **時間単位を設定**（例: 5分単位）
2. **時間軸を分割**（開始時間から終了時間までを5分単位で分割）
3. **各期間の主要なアプリを決定**（その期間で最も長く使用したアプリ）
4. **期間ごとに表示**（時間軸とアプリを横に並べて表示）
5. **色分け**（目的関連・脱線・調査）
6. **時間軸を下部に配置**

## 検証手順
1. Timeline画面を開く
2. 疑似データをロード
3. 時間単位で集約された大まかな画面遷移が表示されているか確認
4. 全体の流れが見やすいか確認
5. 脱線ポイントが分かりやすいか確認

## 考慮事項
- 時間単位の設定（5分？10分？ユーザーが設定可能？）
- 期間が短い場合の表示（例: 1分のセッション）
- ユーザーによるカスタマイズ（時間単位の変更）
