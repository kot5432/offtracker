# Phase 7.5: コア体験検証

## 目的
現在の実装を実際に使い、OffTrackerが本当に「なぜできなかったかを理解する」体験になっているかを検証する。

## 現状の実装（技術検証版として機能）

### 完了している機能
- ✅ Windows APIによるアプリ取得（active-win）
- ✅ イベントベース追跡（1秒間隔のポーリング）
- ✅ サービス検出（Google, YouTube, GitHub等）
- ✅ 基本的なセッションフロー
  - Home → セッション開始 → ウィンドウ追跡 → 終了 → Result → Reflection → Pattern
- ✅ UIとAPIの統合
- ✅ localStorageによる画面遷移

### 技術構成
- Node.js + active-win
- HTTPサーバー（ポート3000）
- JSONファイル保存（sessions, events, results, reflections）
- HTML/CSS/JS UI（5画面）

## 検証方法

### 実際に使用するシナリオ
ユーザーが以下の6つのパターンで実際に作業する：

1. **ケース1: 普通に作業**
   - 意図通りに集中して作業する
   - 目的を達成する

2. **ケース2: 途中で脱線**
   - 作業開始
   - 途中でYouTubeを見る
   - 作業に戻る

3. **ケース3: 難しい問題に遭遇**
   - 作業開始
   - エラー発生
   - 調査に行く
   - 作業終了

4. **ケース4: 時間不足**
   - 作業開始
   - 時間が足りなく終了

5. **ケース5: 目的達成**
   - 明確な目的を設定
   - 達成する

6. **ケース6: 目的未達**
   - 明確な目的を設定
   - 達成できない

## 検証指標

### ① 行動を正しく記録できたか
- ウィンドウ切り替えが検知されているか
- タイムスタンプが正確か
- アプリ名が正確か

### ② 目的と行動を結びつけられたか
- セッションが目的と紺付いているか
- イベントがセッションに紺付いているか

### ③ 結果を記録できたか
- 達成度を選択できたか
- できたことを記録できたか

### ④ なぜできなかったかを振り返れたか
- 原因を選択できたか
- 自由入力で補足できたか

### ⑤ Timelineを見ることで振り返りに役立ったか
- 行動の流れが視覚化されているか
- どこで離脱したかが分かるか

### ⑥ 過去データから繰り返しが見えたか
- 複数セッションを比較できるか
- パターンが検出できるか

## 成功基準

### 最低限の成功
- ✅ ①〜⑥のうち少なくとも4つが「はい」と答えられる

### 完全な成功
- ✅ Pattern画面を見て「自分がなぜできなかったか理解できる」と思える

### 失敗
- ❌ アプリをいろいろ使ったことが分かるだけ
- ❌ なぜできなかったかが理解できない

## 足りないデータの洗い出し

### 確認すべき点
- 「作業が難しかったことを記録する場所がない」等の不足
- Timelineの表示方法の改善点
- Pattern画面の表示内容の改善点
- データ構造の不足点
