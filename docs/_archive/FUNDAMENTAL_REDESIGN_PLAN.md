# OffTracker根本からの再設計プラン

## OffTrackerの根本目的
「やろうと思っていたことができなかった理由を、自分の実際の行動から振り返るためのアプリ」

## 根本的な問い
- ユーザーは本当に「なぜできなかったか」を知りたいのか？
- ユーザーは「どのような行動をしていたか」を知りたいのか？
- ユーザーは「次回どうしたいか」を知りたいのか？

## 現在のアプローチの問題
- 機能が分散している（Home、Result、Timeline、Reflection、Pattern）
- 画面遷移が多い
- 各画面の役割が不明確
- ユーザーにとっての価値が不明確

## 根本的な再設計

### 核心的な価値
ユーザーが「自分の行動を客観的に把握し、目的とのズレを認識し、次回の行動を考える」こと

### 必要な機能（MVP）
1. **目的を設定する**
2. **実際に行動する**
3. **PCが自動記録する**
4. **結果を記録する**
5. **行動を振り返る** ← 核心的な価値
6. **「なぜ」を考える** ← 核心的な価値
7. **次回の行動を考える** ← 核心的な価値

### 不要な機能（MVP）
- 過去の記録と比較（Pattern画面）
- 複雑なサマリー
- 詳細なフィルター機能

## 再設計案

### 案A: 1画面で完結
- **目的設定 → 記録開始 → 記録終了 → 結果記録 → 行動振り返り → 「なぜ」 → 次回の行動**
- すべての機能を1画面で完結
- 画面遷移を排除

### 案B: 2画面で完結
- **画面1**: 目的設定 → 記録開始 → 記録終了 → 結果記録
- **画面2**: 行動振り返り → 「なぜ」 → 次回の行動
- 画面遷移を最小限に

### 案C: 3画面で完結
- **画面1**: 目的設定 → 記録開始 → 記録終了
- **画面2**: 結果記録 → 行動振り返り
- **画面3**: 「なぜ」 → 次回の行動
- 画面遷移を最小限に

## 推奨: 案A（1画面で完結）

### 理由
- 画面遷移を排除
- 一度のフローで完結
- ユーザーにとってシンプル
- MVPとして十分

### 画面構成（案A）
1. **目的設定エリア**: 目的を入力
2. **記録エリア**: 記録開始/終了、現在の状態
3. **結果記録エリア**: 達成度、できたこと、できなかったこと
4. **Timelineエリア**: 行動表示（埋め込み）
5. **振り返りエリア**: 「なぜ」、次回の行動

### メリット
- 画面遷移を排除
- 一度のフローで完結
- ユーザーにとってシンプル

### デメリット
- 画面が複雑になる可能性
- Timelineが小さくなる可能性
